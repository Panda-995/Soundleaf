## 需要处理的问题

### S1 · P1：词典变化的校验没有覆盖首次生成和单段重做

位置：`app/main.py:679–691`、`app/worker.py:699–710`、`app/worker.py:838–849`。

整章生成已增加词典快照比较，这是有效修复的一部分。但词典变更只给 active_audio 非空的章节加过期标记；首次生成结束时即使检测到词典变化，也只保留既有标记，没有创建缺失的标记。单段重做完成逻辑则没有同样的词典快照校验，仍直接从 stale_segments 删除本段下标。

两个已复现路径：

1. 首次生成含两句“灯塔”的章节，在第一次合成调用时保存“灯塔→信号塔”。实际合成文本仍是“灯塔新句甲”“灯塔新句乙”，最终 audio_revision=revision=1、stale_count=0、voice_stale=0，`allow_stale=false` 导出返回 200。
2. 先生成只有第 0 段含“灯塔”的章节，保存“灯塔→信号塔”，开始重做第 0 段；在合成调用时把该词条再次改为“灯塔→照明塔”。本次实际合成“信号塔单段甲”，但完成后 stale_count=0，禁止旧音频的导出仍返回 200。

影响：用户保存的新读音未进入音频，系统却显示成品已更新，导出保护也无法发现。

建议：让整章生成和单段生成使用统一的配置版本校验。首次生成也必须参与失效追踪；完成任务只能清除自己覆盖的输入版本。不要仅依赖某时刻 stale_segments 是否存在。

验收：两条路径都应保留可识别的过期状态并返回 409；按最终词典重做受影响片段后才恢复 200。保持本轮已通过的已有音频整章重做、正常逐段更新行为。

### S2 · P2：词典满 200 条后无法修改已有词条

位置：`app/main.py:658–665`。

数量检查在新增和更新时都会执行。仅相同值的重复保存提前返回；已有词条改成新读音仍被 `COUNT(*) >= 200` 拦截。

实测：连续新增 200 个不同词条全部返回 200；再把已有“词条0”的读音改为“新读音”，返回 400，错误为“每本书最多 200 条读音词条”，总条目仍为 200。

影响：达到允许容量后不能直接纠正现有词条，用户必须删除再添加。

建议：只有旧词条不存在、此次操作会增加数量时才检查上限。验收应分别覆盖第 201 条新增被拒绝、满容量更新成功、删除后新增成功。

### S3 · P2：对比度审计的转换公式仍错误

位置：`scripts/ui-audit.cjs:120–123`、`scripts/ui-audit.cjs:139–144`。

当前仍先做矩阵运算，再将结果立方。正确转换需要先将 l_、m_、s_ 分别立方，再做 RGB 矩阵运算。纯黑纯白自测不含彩度，不能验证这个顺序。

本轮浏览器原生 Canvas 转换的独立对照结果：浅色 red/bg，脚本 4.73:1，浏览器参考 7.42:1；浅色 mint/bg，脚本 5.58:1，参考 5.99:1；深色 mint/bg，脚本 10.38:1，参考 9.91:1。8 位颜色量化不足以解释这些偏差。

这是审计工具的可靠性问题，并非本轮证明页面实际对比度不足。修正公式后应使用非零彩度、多色相以及阈值附近的参考向量验证。

### S4 · P3：读音修正提示把片段数写成章节数

位置：`app/main.py:693`、`frontend/src/components/Pronounce.tsx:109`。

后端 affected 累加匹配片段数，前端却显示“{count} 个已生成章节待重新生成”。同一章多个片段命中时会夸大受影响章节数量。这是源码可直接确认的单位不一致；本轮没有单独模拟弹出该提示。建议统一返回字段及文案单位，使用“个片段”，或另返回去重章节数量。
