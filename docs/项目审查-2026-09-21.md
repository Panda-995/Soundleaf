# 声页项目代码、结构与 UI/UX 审查

日期：2026-09-21。范围：当前工作目录的 app、frontend、测试与部署文档。目录没有 Git 元数据，因此这是当前文件快照审查，不是提交差异审查。没有修改业务代码。

## 结论

现有模块划分和视觉语言可以继续使用，主要风险在角色绑定、音频修订、编辑状态之间缺少一致的约束。自动化检查通过并不能覆盖这些跨功能问题。建议先修 P1，再处理 P2，暂不需要全面重写界面。

## 已确认问题

### 1. P1：修改片段后无法使用片段重生成

位置：app/main.py:1115；frontend/src/pages/Director.tsx:682。

保存脚本一定提升章节 revision；regen-segment 又要求当前音频 revision 与章节一致。因此“编辑一句 → 保存 → 只重生成这句”的主路径必然返回 409，提示先生成整章。与 README 宣称的局部修复能力不符。

隔离 API 复现：保存返回 200，随后 regen-segment 返回 409。建议保存音频对应的脚本快照和片段映射，验证其余片段未变化后允许局部替换；不能简单删除 revision 检查，否则旧时间轴可能拼错位置。

### 2. P1：普通章节保存会覆盖书籍级角色音色

位置：app/main.py:928–944。

章节保存按当前章节的 voice 多数票，无条件 INSERT OR REPLACE 全书 cast。用户先在角色页将角色从 old 绑定为 new，再在导演页保存仍携带 old 的章节，即使只改正文，也会把全书绑定恢复为 old。

隔离复现已确认：绑定 new 后，修改正文并保存，cast 再次变成 old。建议明确书籍角色表为主数据，普通章节保存只补充未绑定角色；改变全书绑定必须是明确的用户动作。

### 3. P1：未保存编辑可因页面导航直接丢失

位置：frontend/src/main.tsx:101、130；frontend/src/pages/Director.tsx:31、259。

dirty 只在导演页本地生效，能禁用章列表切换，但侧栏、切书、重新载入和浏览器离开没有统一保护。main.tsx 的 dirtyRef 没有接入任何逻辑。

浏览器复现：编辑朗读文本 → 点击书架 → 回到 AI 导演，编辑丢失，确认对话框数量为 0。建议将 dirty 注册到导航层，并提供保存后离开、放弃修改、继续编辑；刷新或关闭页面补 beforeunload。

### 4. P2：角色换音色不会使旧音频失效

位置：app/main.py:550–571、1243。

set_cast_voice 只改角色表，不提升受影响章节的 revision。隔离复现中 revision 保持 2 → 2。导出仅比较音频和章节 revision，因而不会将旧角色音色识别为过期。运行中的任务也可能把换音色前的结果标记为当前成品。

建议角色绑定变化与受影响章节的修订更新处于同一事务，任务保存角色、词典、风格快照。修复应与第 1 项的片段版本设计一起完成。

### 5. P2：亮色主题的默认书封标题缺少独立前景色

位置：frontend/src/style.css:706、726。

书封背景固定为深绿色，标题却继承亮色主题的深色正文色。浏览器读到标题祖先颜色为 oklch(0.24 0.018 110)，截图可见默认书封标题几乎不可读。建议封面明确使用自己的浅色标题令牌，不跟随页面正文色。

证据：output/runtime/ui-audit/library-light-1536.png。未将本次截图判断表述为完整 WCAG 合规测试。

### 6. P2：手机端编辑参数排在整章正文之后

位置：frontend/src/style.css:2423–2436；frontend/src/pages/Director.tsx:519、580。

窄屏将章节列表、完整脚本、参数编辑器依序排成单列。点击脚本片段仅改变 index，不打开编辑抽屉或滚动到参数区。390×844 视口、仅两个片段时，参数区起点已经在 y≈1037；长章节会进一步拉大选句与编辑之间的距离。

建议手机端选中片段后直接打开底部编辑面板，保留片段摘要与保存入口，章节切换用紧凑选择器。

### 7. P2：UI 审计发现错误仍会让 CI 成功

位置：scripts/ui-audit.cjs:53、106–126。

溢出、缺焦点、控制台错误等只写入 report，脚本最后固定 process.exit(0)。所以没有抛异常的审计失败不会阻止 CI。对比度检查只解析 OKLCH 明度并比较差值，不能等价于对比度计算；无法解析背景时会静默跳过。本次 checks=[] 不能证明对比度通过。

建议将报告分成 pass/fail/skip，发现失败返回非零退出码；背景色不可解析必须标为未测试，并对实际文字背景计算对比度。

### 8. P2：删除书籍残留读音词典

位置：app/main.py:732–769；app/store.py 的 dict 表定义。

清理删除 cast、chapters 等记录，但遗漏 dict；dict.book_id 没有外键级联。隔离复现中书籍删除成功后仍剩一条词典记录。建议在删除书籍事务中删除 dict。注意重新分章复用了 clear_book_content：重新分章通常应保留书籍词典，不宜不加区分地加入该共用函数。

### 9. P2：AI 分章的查重入队没有取得事务写锁

位置：app/main.py:774–799。

analyze_chapters 使用 store.connect，但在查重前缺少 BEGIN IMMEDIATE；SQLite 默认事务不会因 SELECT 自动取得写锁。两个并发请求可以都读到不存在，再各自插入计费任务。其他分析接口已使用 BEGIN IMMEDIATE，此处与架构文档的原子化声明不一致。

此项为代码路径确认，未对真实服务发起并发计费复现。建议采用已有的原子入队模式，并增加同时请求的去重回归测试。

## 结构与维护性

- 前端已有 pages、共享控件、player、API 类型边界，不建议退回大组件或整体推翻。
- 后端所有路由和业务操作仍集中在 create_app；角色表、章节 revision、任务快照分别在不同接口和 worker 修改，已经产生第 2、4 项一致性问题。优先抽取角色绑定与章节修订服务，再按 books、chapters、jobs、settings 拆路由。
- Director 同时承担脚本编辑、AI 结果采纳、两类任务轮询、重生成、读音编辑和版本试听。建议抽取可保存草稿、任务观察和参数编辑组件，并统一导航保护。
- style.css 约 3800 行，包含后续追加的同名选择器覆盖。可以保留现有令牌，按基础控件、页面、响应式和动效归整，避免继续叠加覆盖规则。
- README 顶部已写角色管理、读音词典和 M4B，但尾部仍将部分能力列为后续范围；开发验证文档也混有旧限制。应建立唯一的功能状态表，区分已实现、模拟验证和真实服务验证。

## UI/UX 分类评价

### 视觉层级

桌面三栏能清楚区分章节、正文和朗读参数；保存、生成、AI 操作可辨识。移动端直接纵向堆叠三栏，参数操作离被编辑内容太远，需要改变布局结构。

### 视觉风格

双主题、黄绿色主操作、统一边框和共享选择控件已有一致性。已确认默认书封在亮色主题的前景色错误；其他视觉判断仅基于本次短篇样例截图，不代表长书、超长标题或所有错误态已覆盖。

### 可访问性

已有键盘可选脚本、共享选择器、焦点样式和减少动效支持。现有自动化对比度检查不可靠；片段选中主要靠 active 样式，未在 role=button 上表达选中状态。读音修正入口依赖正文 mouseup 划选，建议补键盘可访问的词典管理入口。未运行屏幕阅读器人工验收。

### 导航与可用性

首要问题是编辑保护，其次是生成版本语义。用户不应需要理解 revision 才能判断“这段能否重做”或“音色更换是否已经出现在成品中”。移动端应保留选句、编辑、试听、保存的连续操作路径。

### 表单与首次使用

已有配置、导入、空态引导以及禁用状态。用户收到的功能说明应与实际能力一致，尤其是片段重生成；设置连接成功和真实语音质量验收仍需保持区分。
