## 剩余问题

### T1 · P1：单段重生成会清除生成期间新增的词典过期状态

位置：`app/worker.py:590–594`、`app/worker.py:699–710`。

复现步骤：

1. 生成两段正文，仅第 0 段包含“灯塔”。
2. 保存词典“灯塔→信号塔”，重生成第 0 段。
3. 在合成调用期间将同一词条改成“灯塔→照明塔”。
4. 等本次重生成完成后，以 `allow_stale=false` 请求导出。

本轮实测：合成输入为“信号塔单段甲”，尚未应用最终的“照明塔”；完成后 stale_count=0，导出返回 200。

原因：单段重生成先读取词典，完成时仅检查章节 revision，再无条件从 stale_segments 删除当前下标。词典修改不递增该 revision，因此同一个下标上的较新配置变更被旧任务清掉。整章生成分支已有词典快照比较，但单段分支仍未接入相同校验。

影响：错误读音会被显示为最新，禁止旧版本导出仍无法阻止它。

建议：将任务开始时使用的词典/片段输入版本纳入单段任务完成校验，并与失效标记写入保持一致的事务规则。只解除本任务实际覆盖的版本，不能仅凭片段下标相同清除标记。

验收：上述路径完成后仍保留过期状态、导出返回 409；随后按最终词典重做该段才清除状态并返回 200。保留本轮已通过的首次生成和整章重做行为。

### T2 · P2：对比度审计仍使用错误的 OKLCH 转换顺序

位置：`scripts/ui-audit.cjs:120–123`、`scripts/ui-audit.cjs:139–144`。

仍然先将 l_、m_、s_ 代入 RGB 矩阵，再把结果立方；正确顺序是先分别立方，再做矩阵运算。纯黑和纯白测试不含彩度，不能识别此错误。

本轮实际浏览器颜色转换对照：

| 配色 | 脚本结果 | 浏览器参考结果 |
| --- | --- | --- |
| 浅色 red/bg | 4.73:1 | 7.42:1 |
| 浅色 mint/bg | 5.58:1 | 5.99:1 |
| 深色 mint/bg | 10.38:1 | 9.91:1 |

独立参考使用浏览器 Canvas 的 sRGB 结果，有轻微 8 位量化误差，但不足以解释上述偏差。这里确认的是检测工具错误，没有据此判定页面实际对比度不合格。

建议：修正公式，并用非零彩度、多色相及阈值附近的参考用例验证。当前 UI 审计通过不能作为可靠的对比度验收结论。

### T3 · P3：读音修正提示中的数量单位仍不一致

位置：`app/main.py:695`、`frontend/src/components/Pronounce.tsx:109`。

本轮创建一章两段均含“灯塔”的正文，保存词典返回 affected=2。前端仍把这个数代入“2 个已生成章节待重新生成”，但实际只有一章。后端返回片段数量，前端应显示片段，或另行返回去重后的章节数。

此外，当前词典接口会标记尚无音频的章节，文案中的“已生成”也不再准确。建议按实际状态写为“{count} 个片段的读音已更新，生成时生效”，或分别提示已有音频待重做的数量。

本项通过接口结果和当前前端源码交叉确认，未单独执行选词弹窗的端到端提示测试。
