## 优先处理的问题

### A1 · P1：保存请求期间继续输入，响应会覆盖新编辑

位置：`frontend/src/pages/Director.tsx:340–348`。

点击保存后，正文输入仍可继续编辑；保存响应到达时，代码直接 `setDetail(d)` 并清除 dirty。响应对应的是点击保存时的旧快照，并不包含请求期间的新输入。

隔离 Chromium 使用当前构建、延迟 API 响应复现：请求期间输入“保存请求期间继续输入的正文”，响应后恢复为“点击保存时的正文”，保存按钮禁用，新增编辑消失且不再提示未保存。

建议：保存时记录本地编辑序号，只在没有后续编辑时整体替换；有后续输入时更新服务端 revision，同时保留本地内容与 dirty。或者在保存窗口明确禁用编辑。

验收：延迟保存响应期间继续输入，响应到达后新输入保留且仍可保存；正常无后续输入的保存能解除 dirty。

### A2 · P1：忽略 AI 分段建议会丢失未保存正文

位置：`frontend/src/pages/Director.tsx:578–588`。

有 AI 分段建议时，用户可先修改当前脚本，再点击“忽略本次建议”。该操作只应撤销建议，但 POST 后又获取服务端整章并覆盖本地 detail。

当前构建的隔离浏览器实测：未保存文本恢复为“原始正文”，未保存提示却仍存在。已编辑正文被直接丢弃，没有确认。

建议：只清除本地 restructure 字段；如果需要重新取服务器状态，应合并建议状态而不覆盖草稿。

验收：修改正文、音色或参数后忽略建议，所有本地编辑保持不变，建议消失，dirty 状态仍正确。

### A3 · P1：生成期间换角色音色，再重做一段即可导出混合音色

位置：`app/worker.py:962–968`，关联 `app/worker.py:803`。

复现：同一角色两句台词使用 old 音色；整章生成第一句期间把角色绑定改为 new。该任务两句仍使用 old。完成时，词典没有变化，整章生成分支清空角色更新产生的 stale_segments；此时 voice_stale=1 暂时拦截导出。仅重做第一句为 new 后，拼接成品被标为最新 cast_version，剩余第二句仍为 old。

隔离数据库、模拟 TTS 与真实 FFmpeg 实测：第一次完成后 stale_count=0、voice_stale=1、导出 409；重做第一句后 stale_count=0、voice_stale=0、`allow_stale=false` 导出 200。合成调用记录依次为 old、old、new。

建议：整章完成时同时核对角色配置快照，保留生成期间新增的角色片段失效标记；局部完成只能解除本段实际覆盖的版本。

验收：只更新第一句后继续拦截导出，第二句也更新为最终音色后才恢复 200。

### A4 · P1：发布版本配置不一致，两套发布门禁必然失败

位置：`.github/workflows/docker-publish.yml:10`、`:74`；`.github/workflows/build-ugreen-upk.yml:20`、`:40`；`ugreen/soundleaf-app/rootfs_common/docker-compose.yaml:3`。

`pyproject.toml` 和 UGOS 元数据已为 1.2.0，但两套工作流 APP_VERSION 仍为 1.1.0，UGOS 内部 Compose 也固定旧镜像。Docker 工作流要求源码版本匹配 APP_VERSION，UPK 工作流要求包元数据匹配 APP_VERSION；本地复算两项匹配均为 false。

影响：当前提交的镜像和 UPK 发布会被版本门禁阻止。即使单独绕过门禁，包中的镜像引用也仍指向旧版。

建议：保留门禁并统一版本来源，同步工作流、包元数据和镜像引用。验收需在修复后真实运行两套发布流程；本轮未执行 Actions 或发布镜像。

### A5 · P1：AI 调用中途重启后自动重发，违反已声明的计费保护

位置：`app/worker.py:248–253`，关联 AI 调用阶段 `:520–526`、`:569–576`、`:667–669`。

启动恢复只把“请求语音服务”“AI 绘制封面”“分析书籍资料”三个阶段设为 needs_review，其他 running 任务一律重入 queued。实际朗读分析、语义分段和章节识别使用其他阶段名，所以远端 AI 请求尚不确定时重启，会自动重新提交。

隔离恢复探针分别写入上述三个真实阶段并调用 Worker.start（模拟线程启动，避免任何真实网络请求），三者全部变为 queued/恢复任务；语音请求对照为 needs_review。恢复后的消费路径会重新执行 AI 调用。

这与 `ARCHITECTURE.md:25` 的“绝不自动重发可能已计费的请求”、产品计划中“不无提示地重复提交未知结果的付费请求”冲突。本轮没有发生真实重复计费。

建议：持久化明确的请求状态，而非按展示用阶段文字识别计费窗口；未知结果进入人工确认，或使用服务支持的幂等/结果查询机制。验收覆盖所有远端 AI/合成调用及批次边界。

## 其他需要修复的问题

### A6 · P2：中文词典稳定不变，逐段重做仍无法清除过期标记

位置：`app/worker.py:708`、`:822–827`。

开始时的词典快照用 `json.dumps(..., ensure_ascii=False)`，结束时用默认 ensure_ascii=True；同一中文词典也被判断为不同。

实测把两段“灯塔”改读“信号塔”后逐段重做，TTS 输入均正确，但全部完成后 stale_count 仍为 2、正常导出返回 409。

建议：直接比较规范化内容，或统一序列化选项。必须同时验证“稳定中文词典能清标记”与“生成期间变化不能清标记”，防止只修其中一条路径。

### A7 · P2：同页第二次 AI 分章完成后，页面一直显示处理中

位置：`frontend/src/pages/Chapters.tsx:106–129`、`:221–222`。

第一次终态详情会把 effect 内 detailFresh 设为 false；再次启动新任务没有重置该标记。任务列表继续轮询，但新任务详细结果不再刷新。

当前构建隔离浏览器实测：第二次任务后端为 succeeded，界面仍为“处理中 / 新任务运行中 / 0/1”，新任务详情只读取一次，而任务列表读取四次。

建议：将详情刷新状态绑定任务 ID；发现不同 ID 时重置，避免一个任务的终态控制后续任务。

验收：同页连续识别两次，第二次也能展示完成预览，无需离开页面或重载。

### A8 · P2：首次音频加载尚未完成时切书，旧书音频仍会载入

位置：`frontend/src/main.tsx:162`，关联 `frontend/src/player.ts` 的 playSeq/reset。

切书只在 audioMeta 已存在时调用 reset。首次元数据请求尚未返回时 audioMeta 为 null，不会取消该请求；旧响应随后仍通过序号校验并加载旧书音频。

隔离浏览器延迟元数据响应验证：当前选中“第二本书”，播放器却载入 `/api/audio/a1`，显示第一本书的“第一章”。

建议：每次书籍身份变化都取消在途播放请求，无论当前是否已有 audioMeta。验收覆盖首次播放加载、已有音频播放、快速连续切书。

### A9 · P2：孤儿文件清理误删正在上传的封面

位置：`app/worker.py:351–358`、`app/main.py:1135–1137`。

上传先写封面文件，再更新数据库引用；清理线程获取已引用文件集合后立刻删除集合外文件。worker 不与自身任务同时写入的假设，无法覆盖 HTTP 请求线程。

确定性交错验证：上传文件写入后、引用更新前执行 sweep_orphans。上传返回 200，数据库有封面路径但文件不存在，随后 GET 封面返回 500。

建议：HTTP 文件提交与清理共享安全的锁/暂存提交协议，或给新文件宽限期并再次校验引用。验收同时覆盖正常上传、替换、清理并发和真正遗留文件回收。

### A10 · P2：对比度审计转换公式仍错误

位置：`scripts/ui-audit.cjs:113–116`、`:132–137`。

OKLCH 转换仍先乘 RGB 矩阵再立方，正确顺序应先将三个 LMS 分量分别立方。黑白自测无法识别彩色运算顺序错误。

本轮浏览器 Canvas 独立对照：浅色 red/bg 为脚本 4.73:1、浏览器参考 7.42:1；浅色 mint/bg 为 5.58:1 对 5.99:1；深色 mint/bg 为 10.38:1 对 9.91:1。

这是检测工具可靠性问题，本轮没有由此证明实际页面配色低于标准。建议修正公式并增加非零彩度、多色相和阈值参考用例。

## 结构与 UI/UX 观察

### 结构

前端已按页面、共享控件、播放器和接口拆分；新增本地 TTS 模块及模型管理，职责边界比早期清楚。当前具体结构缺陷是状态规则分散：整章/单段音频完成规则不一致（A3/A6），异步响应没有统一保护草稿（A1/A2），恢复策略依赖展示阶段字符串（A5），文件清理缺少跨 HTTP 与 worker 的提交规则（A9）。这些应先用共享规则与明确状态模型解决。

### 视觉层级

桌面导演页章节、脚本与参数区域清晰，主生成操作可辨识。手机主要页面未发现横向溢出或主操作遮挡。抽查桌面浅色导演与手机本地引擎设置截图，标题、卡片、操作分组和播放器布局正常。

### 视觉风格

深浅主题及常用控件保持一致。手机设置页多标签较拥挤，出现单字折行；可考虑可横向滚动的标签栏、缩短标签或明确两行布局，提高扫读效率。这是轻量改进建议，未列为本轮阻断问题。

### 可访问性

Select 键盘操作、Escape 与焦点恢复等现有检查通过；UI 脚本的焦点与减弱动态效果检查也通过。对比度工具受 A10 限制；触控检测仍使用 32px 阈值，不能视为所有控件均达到 44px。未开展完整读屏工具验证。

### 操作与反馈

默认账户登录及首次改密、导入、生成、试听、进度恢复、ZIP 下载、AI 分章/分段/导演建议、删除书籍以及本地模型管理入口的主流程通过。A1/A2 是未保存编辑保护缺口，A7/A8 是重复操作与切换时的反馈/上下文缺口，现有成功路径测试未覆盖它们。
