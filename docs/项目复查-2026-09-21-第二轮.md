## 需要处理的问题

### F1 · P1：部分重生成将其他未完成修改一并标为最新

位置：app/main.py:1127–1150；app/worker.py:661–676。

目前只去掉了旧音频与脚本 revision 不一致时的拒绝逻辑，没有保存音频对应的脚本快照，也没有确认非目标片段未变化。worker 重做一个 index 后直接把整章音频写为最新 revision。

真实处理链复现（模拟合成音频 + 实际 FFmpeg）：同时修改第 1、2 段，保存为 revision 2，只重做第 1 段。合成调用记录只有“第一段新内容。”，第 2 段仍是旧音频，但返回 audio_revision=2、script_revision=2；allow_stale=false 的导出仍返回 200。

这会让用户把未完成修订的音频当作完整成品交付。分段结构改变时，仅检查 index 存在也无法确认该位置仍属于原来的片段。

修复：保存成品使用的稳定片段 ID、文本与参数指纹、全书声音配置快照；只有所有片段都与当前脚本一致时才将整章标为最新。结构无法对应时明确要求整章生成。

### F2 · P1：末段和停顿修改的拼接范围错误

位置：app/worker.py:619–647；app/audio.py:119–134。

完整合成只在非末段后追加停顿。局部重生成却统一从旧时间轴跨度中减去“当前脚本”的 pause，并假设旧音频含有同样的停顿。末段没有该停顿，修改后的 pause 也不等于旧 pause。

两个定向复现：

- 三段各 0.1 秒，原成品 0.8 秒；最后一段换成同样 0.1 秒的新音频，结果变成 0.9 秒，时间轴终点却为 1.05 秒。旧末段音频没有被完整替换。
- 第一段停顿从 250ms 改成 500ms 后重做，正确总时长应为 1.05 秒，实际为 0.9 秒；第 1 段 end=0.6，第 2 段 start=0.45，时间轴出现重叠。

修复：时间轴明确存储 speech_end、pause_end 或实际停顿长度；按旧片段完整跨度替换新语音及新停顿，末段单独处理。最后校验时间轴单调、无重叠且不超出 WAV 总时长。

### F3 · P1：导航保护仍可绕过

位置：frontend/src/main.tsx:173、419、463；frontend/src/pages/Director.tsx:285、332。

新增 tryGo 只覆盖部分入口。浏览器 hashchange 直接改路由，Logo 是未拦截的链接，“重新载入”直接覆盖 detail；退出登录同样未走守卫。

浏览器验证：普通侧栏触发 confirm，取消后留在导演页，说明这条路径已修复。另行测试 Logo、浏览器返回和重新载入，三者均无确认，重新打开后“未保存标记”消失。退出登录绕过为源码确认。

修复：统一离开/覆盖编辑状态的入口，处理浏览器前进后退、Logo、切书、退出和重新载入。切书当前先 tryGo、再 go，会重复执行同一守卫，也应一起归一化。

### F4 · P2：手机“章节列表”标签实际显示参数页

位置：frontend/src/style.css:3739–3745。

选择器 `.pane-chapters .chapter-nav` 在章节模式下隐藏了应显示的章节列表，却没有隐藏 inspector。

390×844 实测：

| 当前标签 | 章节列表可见 | 正文可见 | 参数可见 |
|---|---|---|---|
| 章节列表 | 否 | 否 | 是 |
| 朗读脚本 | 否 | 是 | 否 |
| 朗读设置 | 否 | 否 | 是 |

用户无法通过这个标签选择下一章。修复隐藏规则并为三个标签逐一断言内容正确；标签还应补键盘方向键、焦点和 tabpanel 关联。

截图：output/runtime/reaudit-mobile-章节列表.png。

### F5 · P2：首次生成中换角色音色仍会生成错误“最新版本”

位置：app/main.py:577–581；app/worker.py:701–717、788–791。

版本更新只覆盖 active_audio IS NOT NULL 的章节。首次生成尚无音频时换音色，正在运行的任务已经读取旧 cast，而修改不会提升章节版本，最终仍可把旧声音提升为当前音频。

定向复现：第一次合成调用时将角色从 old 改为 new，实际两段均使用 old；章节版本始终为 2，成品音频也标为 2。普通章节保存保留 new 的修复在此场景下仍有效，问题是任务与成品的版本归属。

修复：版本失效不能以“是否已经有成品”为前提；对确实受声音变更影响的章节统一提升修订，任务捕获并遵守角色、词典和风格快照。词典接口有相同的 active_audio 条件，应一并检查。

### F6 · P2：有 PNG/JPG 封面时 M4B 导出失败

位置：app/audio.py:158–171。

命令先添加 `-map`、编码等输出选项，再添加封面的 `-i`，导致 FFmpeg 把这些选项归到图片输入。

使用有效的本地测试 PNG、已生成章节、实际 FFmpeg 复现导出失败。stderr 明确报告：`Option map ... cannot be applied to input url ...png`，随后为 `Error opening input files: Invalid argument`。现有 M4B 测试没有覆盖位图封面路径。

修复：先列出全部输入，再追加 stream mapping、metadata 和编码输出选项。补有封面、无封面两条实际导出测试，并检查视频附件流与章节导航。

### F7 · P2：AI 分章并发请求仍会重复创建任务

位置：app/main.py:792–809。

仍未在查重前执行 BEGIN IMMEDIATE。使用两个并发 API 请求，在查重后、实际入队前设置测试屏障，让两个请求都读到无任务；两次响应均为 200，产生 2 个不同任务 ID。这是可发生的线程交错，测试没有绕过正常数据库写入。

所有任务都在隔离数据中，worker 未运行，也未调用付费服务。实际启用 worker 后，两条队列项都可能调用分析服务。

修复：沿用其他分析接口的原子入队方式，补并发查重回归。不能只在前端禁用按钮。

### F8 · P2：删除成功后仍残留书籍词典

位置：app/main.py:772–782；app/store.py:75–76。

删除事务仍未删除 dict；表也没有对应外键级联。隔离复现确认书籍 DELETE 返回 200，按该 book_id 查询仍剩 1 条词典。

修复：只在删除整本书时显式清理词典；重新分章与删除共用 clear_book_content，不能误删重新分章时应保留的词典。

### F9 · P2：对比度检查仍没有有效验收结果

位置：scripts/ui-audit.cjs:106–128。

新的非零退出码已修复“记录错误却成功退出”的问题，但对比度仍使用 OKLCH 明度差而非对比度。body 背景无法匹配正则时会静默跳过。本次 dark/light 均未输出任何 CONTRAST 检查记录，不能据 checks=[] 宣称该项通过。

此外，当前有效解析时无论结果是 `ok` 还是 `TOO LOW` 都会 push 到 checks；新加入的 checks.length 判定会把记录成功检查也当失败。

修复：结构化保存 pass/fail/skip，计算实际合成背景与文字颜色，只有 fail 决定失败退出。明确记录跳过项。补移动端标签交互断言，避免 F4 这种无溢出却不能操作的页面通过巡检。

## 结构、UI/UX 评价

### 代码与架构

本次未见角色/修订/任务快照的统一服务层。F1、F2、F5 说明新增局部处理需要完整版本模型，单独放宽接口条件会破坏成品一致性。优先建立声音快照与时间轴模型，再考虑拆路由和组件；只拆文件不能解决这些错误。

接口仍由 main.py 统一注册，worker 按任务类型集中处理；前端已有页面模块、API 类型、共享选择器和播放器。现有基础可以保留。Director 仍同时管理编辑、分析、重生成、读音和导航状态，建议后续按职责抽取。

### 视觉层级

桌面章节、正文、参数分区仍清晰。手机改成标签方向合理，但章节标签功能错误；修复后需在长章节中验证选句—参数—试听—保存的连续性。

### 视觉风格

默认书封的亮色前景色已修复，当前截图中主题、主按钮与面板风格一致。本次双主题三宽度巡检未发现横向溢出。不建议因本轮结果全面重做视觉设计。

### 可访问性

共享 Select 的键盘、Escape 和焦点恢复已在浏览器主流程通过。新手机标签还缺完整 tabpanel/焦点语义；脚本选中仍主要靠视觉 class，读音编辑仍依赖划选。没有做屏幕阅读器人工验收，对比度也不能判为全量通过。

### 导航、表单与反馈

新增未保存确认对普通侧栏有效，保护范围仍不完整。重生成反馈不能仅以 job succeeded 代表整章已更新；用户需要知道哪些片段仍与脚本不一致。当前错误是可交付音频与 UI 状态不一致，优先级高于视觉微调。
