## 仍需处理

### Q1 · P1：换全书角色音色后重做一段，整章旧声音被标为已更新

位置：app/worker.py:573–574、671–685。

局部重生成会读取当前 cast_version，然后给新拼出的整章音频写入该版本。其余未重做片段仍来自旧成品，却没有保留各自的旧声音状态。

定向复现：

1. 同一个角色有两句台词，以 old 音色生成完整章节。
2. 在角色表将该角色绑定改为 new。
3. 只重生成第一句。
4. 合成调用只包含第一句、voice=new；第二句仍为 old。
5. 书籍详情 voice_stale=0，allow_stale=false 的导出返回 200。

影响：成品同一角色混用新旧音色，系统却显示全章已更新。此前“生成过程中换声音”的整章路径已经修复，本项是局部拼接对未改片段的版本归属仍不完整。

建议：局部成品的状态必须由全部实际片段的声音快照决定。可先采取保守规则：源成品声音配置已过期时，拒绝用单段重生成清除全章过期标记，提示完整生成；长期使用片段级声音指纹/版本追踪，全部受影响片段更新后再解除过期状态。

### Q2 · P1：词典改动没有登记受影响片段，单段重做即可错误通过导出

位置：app/main.py:603–645；app/worker.py:674–714。

词典修改只提升章节 revision，没有填充受影响片段的 stale_segments。局部重生成直接创建当前 revision 的整章音频；没有其他过期片段记录可保留，因此其余旧读音被当作最新。

复现：两段都含“灯塔”，生成后添加“灯塔→信号塔”，仅重做第一段。合成调用只有“信号塔第一句。”；第二段仍是旧读音。结果 audio_revision=revision=2、stale_count=0、voice_stale=0，禁止旧音频的导出仍返回 200。

建议：词典新增、修改、删除均应追踪所有受影响片段，或者在配置变更时要求完整重生成。朗读风格/默认音色等书级参数也应采用同一规则，避免只有直接编辑脚本才登记 stale_segments。后一类参数本轮为代码审查扩展建议，不冒充已经逐项复现。

### Q3 · P2：切换书籍仍重复确认

位置：frontend/src/main.tsx:149–159。

普通路由的重复确认已修复，但 selectBook 先 tryGo(target)，更新状态后又 go(target)，第二次 go 再次执行同一守卫。

浏览器复现：在导演页编辑未保存内容，通过“当前书籍”选择另一测试书籍，接受确认后共收到 2 个 confirm。普通侧栏相同操作只有 1 个，说明剩余问题局限在切书路径。

建议：selectBook 只执行一次授权与导航；确认后不可在已变更书籍状态的途中再次询问。回归同时验证接受、拒绝及目标书籍是否保持正确。

### Q4 · P2：对比度计算中的 OKLCH 转换顺序错误

位置：scripts/ui-audit.cjs:120–123。

脚本已不再静默跳过颜色，并开始检查配色令牌。但转换公式先对 l_/m_/s_ 做 RGB 矩阵变换，再将结果立方；应当先将三个 LMS 分量分别立方，再进行线性 RGB 矩阵变换。这两种操作不能交换。

独立验证使用浏览器 Canvas 将实际 CSS 颜色绘制为 sRGB 像素，再计算相对亮度。例子：

| 配色 | 当前脚本计算 | 浏览器像素参考 |
|---|---:|---:|
| 暗色 mint/bg | 10.38:1 | 9.91:1 |
| 亮色 red/bg | 4.73:1 | 7.42:1 |
| 亮色 on-lime/lime | 9.92:1 | 9.61:1 |

以上抽样本身均未低于 4.5:1，本报告不据此声称这些文字不合格。问题是自动化门禁采用了错误计算，未来边界色可能被误判；当前颜色解析也只覆盖部分 CSS 语法，未处理透明叠加。

建议：使用经过验证的转换实现，或浏览器解析后的颜色作为输入；对当前实际使用的配色分别记录通过结果。令牌检查只是抽样，不能替代实际文字背景、透明图层、控件状态的全面无障碍审计。

## 代码结构与 UI/UX

**结构**：路由、整章合成、局部合成、词典、书籍设置各自维护修订规则。Q1/Q2 的共同原因是“章节最新”仍主要从一次局部操作推导，而不是根据完整音频中各片段的实际输入判断。优先统一这一约束；仅增加版本字段或界面提示不足以保证一致性。

**视觉层级**：桌面三栏、手机三标签的核心分区已经可用。当前巡检未见横向溢出；手机章节入口和选中状态截图正常。

**视觉风格**：双主题与共享控件保持一致，已修的默认书封对比问题没有复现。没有需要整体重做视觉方案的证据。

**可访问性**：共享 Select 的键盘、Escape、焦点恢复通过主流程；新对比度门禁仍有 Q4 计算缺陷。未进行屏幕阅读器人工验收。

**导航与反馈**：普通侧栏、Logo、浏览器返回和重新载入的草稿保护已通过；切书重复确认仍需处理。成品提示的可信度仍受 Q1/Q2 影响，这是本轮 UX 的首要问题。

**部署补充**：.dockerignore 仍允许 app/**，没有明确排除 app/data 和临时日志；上轮已记录这会把本地运行数据纳入 COPY app/。本轮未构建镜像，也不宣称发生数据泄露。该清理建议仍保留，不计入以上 4 项核心发现。
