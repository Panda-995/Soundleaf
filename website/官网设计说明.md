# 声页官网设计说明

> 对应交付物：[`index.html`](index.html)（单文件、零依赖、可直接静态托管）。
> 本文档按"首页信息架构 / 核心卖点 / 功能模块 / 视觉 / 动效 / 响应式 / 可访问性"分区，说明每项设计如何对应项目属性。预览截图见 [preview/](preview/)。

## 0. 总纲：官网策略

产品自己的 `PRODUCT.md` 把「营销首页」列入了 anti-references——那是对**产品界面**的要求；官网要卖东西，但不能长成喧闹的 SaaS 落地页。因此官网策略定为：

**「官网即产品第一章」**：沿用产品既有的墨黑 + 淡黄绿 + 衬线书名的视觉语言、沿用产品内虚构演示书《雾海来信》与角色（旁白·远山 / 林舟 / 沈雾）、沿用「动效只用于状态与反馈」「音频不自动播放」「不伪装真实音频」的产品原则。趣味性来自"能玩的产品演示"，而不是装饰堆砌。

| 项目属性 | 官网策略 |
| --- | --- |
| 品牌人格「沉静、细腻、专业」（PRODUCT.md） | 大量留白、衬线标题、克制的 Lime 强调色，不使用渐变横幅、倒计时、弹窗 |
| 反参照「霓虹赛博 / 营销大屏」 | 无 3D 装饰、无数据大屏元素、无夸张营销话术 |
| 演示书《雾海来信》已是产品界面稿素材 | 官网沿用同一本书、同一批角色名，品牌认知连续 |
| 产品原则「AI 输出永不直接采用」「原文不改」 | 文案直接把这条铁律写成卖点：「AI 出建议，你来拍板」 |
| 单账户自托管工具，非 SaaS | CTA 是「一行命令部署」而非「注册试用」，无邮箱收集 |

## 1. 首页信息架构

单页锚点式结构，从「是什么 → 为什么 → 怎么做 → 怎么装」四层递进：

| # | 区块 | 锚点 | 承担的信息任务 | 对应项目属性 |
| --- | --- | --- | --- | --- |
| 1 | 顶栏 | — | 品牌 + 5 个锚点 + 主题切换 + GitHub | 产品「侧栏底部一键切换主题」习惯的延续；仓库是主要转化出口 |
| 2 | Hero | `#top` | 品牌句 + 一段话定位 + 双 CTA + 交互演示播放器 + 特性徽章行 | 品牌标语「让文字，被听见」直接取自产品登录页；播放器复刻「试听」页构图 |
| 3 | 核心能力 | `#features` | 4 张卖点卡 + 「十个页面」清单条 | 每张卡底部有 `↳ 对应实现` 溯源行，指向真实页面/机制 |
| 4 | 制作流程 | `#workflow` | 4 步时间线 | 按产品真实工作流排序：导入 → 角色 → 精修 → 导出 |
| 5 | 声音与 AI | `#voices` | 双引擎卡片 + 情绪风格互动演示 | 云端(MiniMax/兼容) 与本地(Kokoro/ZipVoice) 双引擎是 v1.2.0 核心更新 |
| 6 | 部署 | `#deploy` | Docker 命令（可复制）/ UGOS Pro / 源码三卡 + 3 条部署要点 | 双架构 GHCR 镜像、绿联 UPK 是项目实际分发渠道 |
| 7 | FAQ | `#faq` | 6 个原生 `details` 折叠 | 覆盖硬件、密钥、格式、隐私、多人、音质六个真实决策点 |
| 8 | 结尾 CTA + 页脚 | — | 复读品牌句 + 部署/下载双按钮 + 文档链接 | 页脚声明 AGPL-3.0、v1.2.0、零追踪 |

信息顺序的理由：目标用户（小说作者 / NAS 用户 / 独立创作者，见 PRODUCT.md）先被「把我的书做成有声书」吸引（Hero），再被「不只是 TTS 套壳」说服（卖点），确认流程可掌控（流程），评估声音与隐私（声音与 AI），最后落到部署成本（部署）——与自托管工具的评估路径一致。

## 2. 核心卖点表达

四张卡片全部从**产品机制**反推，而非泛泛的"高质量/易用"：

| 卡片 | 表达 | 对应项目属性（机制级） |
| --- | --- | --- |
| 01 逐章工作室，改一句只重做一句 | 「一键生成的有声书能听，但不耐听」——把竞品对比写进开头 | `regen_segment` 片段级就地重合成、章节工作台逐段参数编辑 |
| 02 让每个角色，各有其声 | 引号内对白/引号外旁白自动拆分 | `worker.resolved_segment` 引号边界拆分、书级 cast 表、角色库批量换声 |
| 03 AI 出建议，你来拍板 | 把架构铁律「AI 输出永不直接采用」翻译成用户利益 | AI 导演说话者标注、21 种情绪、读音词典划选修正、建议可撤回 |
| 04 数据与声音，都留在你手里 | 自托管 + 可选离线写成一句话信任状 | 单容器单数据目录、Kokoro CPU 离线合成、Fernet 加密密钥、无 GPU/特权模式 |

卖点区结尾的「十个页面，各司其职」胶囊条（书架 → 设置），用产品真实的信息架构本身当证据——这是自托管工具独有的可信度信号。

## 3. 功能说明模块

功能不做成 20 项的平铺清单，而是**按用户任务分三处表达**：

1. **卖点卡**承载差异化的 4 项（见上）；
2. **流程时间线**承载使用顺序中的功能（自动分章/拆分合并、AI 分段标注、读音词典、情绪与语速、先试听后批量、M4B/ZIP 导出），每步挂 `对应页面` 标签；
3. **声音与 AI 区**承载引擎与声音工程能力（MiniMax 与 `/audio/speech` 兼容、限流自动重试、Kokoro 103 音色、ZipVoice 克隆、响度归一化、词典高亮）。

未塞进官网的长尾功能（键盘快捷键、播放进度记忆、i18n 等）留给 GitHub README，官网只保留决策相关功能——对应产品原则「先试听，后批量；提交前显示范围与能力」的克制气质。

## 4. 视觉风格方向

**继承产品 `DESIGN.md` 的语义令牌体系**，OKLCH 色板经脚本换算为 sRGB 并逐对实测 WCAG 对比度（全部 ≥ 4.5:1，多数 ≥ 7:1）：

| 令牌 | 暗色（默认） | 亮色 | 用途 | 实测对比（文字对） |
| --- | --- | --- | --- | --- |
| `--bg` | `#0a0a08` | `#f7f7f3` | 页面底 | 正文/底 17.2:1（暗）· 14.4:1（亮） |
| `--surface` | `#141411` | `#fffffd` | 卡片 | 次级文字/面 7.7:1 · 7.8:1 |
| `--raised` | `#1e1e1a` | `#ebece6` | 控件/代码块 | — |
| `--text` | `#efefe9` | `#24251e` | 正文 | — |
| `--muted` | `#a8a8a0` | `#53534b` | 次级文字 | 8.3:1 · 7.2:1 |
| `--primary` | `#e3e676` 淡黄绿 | `#446401` 叶绿 | 主按钮/强调 | 按钮字/底 13.9:1 · 6.6:1 |
| `--accent` | `#5fc6b3` 青 | `#006768` | 链接/青色音轨 | 9.6:1 · 6.2:1 |
| `--role-a / --role-b` | 青 `#6eacd7` / 玫 `#d887ae` | `#1f6a96` / `#94436d` | 角色「林舟 / 沈雾」的音轨色 | 7.5:1 / 7.0:1（暗，图形用） |

- **字体**：标题与书名用衬线（Noto Serif SC 栈，文学质感，对应产品「书封可用衬线字体」）；正文系统无衬线；命令与时间码等宽字体 + `tabular-nums`（对应产品「时间码使用等宽数字」）。
- **亮度双主题**：与产品完全一致的双主题策略，`prefers-color-scheme` 初始化、手动切换、localStorage 记忆，两套主题共享同一组语义令牌。
- **圆角与间距**：4px 基数、控件 11–13px 圆角、卡片 14–16px，沿产品「圆角随层级递增」。
- **演示书封**：纯 CSS/SVG 绘制的《雾海来信》——深海渐变 + 一道灯束 + 竖排书名，致敬产品 AI 封面的氛围而不依赖图片资源。

## 5. 交互动效设计

总原则来自产品 `DESIGN.md`：「动效只用于状态与反馈」「播放键播放中缓慢呼吸」「暂停即静止」，官网逐条继承并说明用途：

| 动效 | 位置 | 参数 | 服务什么信息 | 对应产品动效 |
| --- | --- | --- | --- | --- |
| Hero 逐层进场 | 首屏 | 260–650ms，错峰 80ms，仅 opacity+translateY | 建立阅读顺序：眉题→标题→副文→CTA→播放器 | 页面进入淡入 |
| 波形播放动画 | 演示播放器 | 1.5s 交替 scaleY，逐条错峰 | 表达"正在播放"；暂停立即静止 | 播放键呼吸、真实波形 |
| 音色切换换色+重新赋形 | 演示播放器 | 颜色 450ms、高度 550ms 过渡 | 可视化"角色各有其声"，青/玫/绿即角色音轨色 | 导演页角色色音轨 |
| 播放键呼吸光晕 | 演示播放器 | 3.2s box-shadow 循环 | 播放中状态（暂停即消失） | 「播放键在播放中缓慢呼吸」 |
| 封面高光掠过 | 演示播放器 hover | 1s 单次 translate | 书卡可感的"实物感" | 「书卡悬停抬升与封面高光掠过」 |
| 滚动进场 | 各区块 | threshold 0.12、触发一次、子项错峰 | 控制单屏信息密度，非滚动噱头 | 列表逐项错峰淡入 |
| 卖点卡/流程点 hover 抬升 | 卡片 | 300ms translateY(-4~5px)+描边染色 | 指示可聚焦单元，无位移的纯装饰 | 书卡悬停抬升 |
| 情绪胶囊切换 | 情绪演示 | 180ms 颜色过渡 + 2px 抬升 | 参数读数随情绪更新（aria-live） | 情绪标签选中态 |
| 复制按钮反馈 | 部署区 | 文案换成「已复制 ✓」1.8s + aria-live | 遵守产品「不能只闪一下 Toast」 | 状态必须可读 |
| 环境光晕漂移 | 全页背景 | 2 片、70s 循环、仅 transform、≤11% 饱和 | 长时间阅读的最低限度生命感 | 「两片极低饱和光晕 70s 缓慢漂移」 |

三条纪律：所有动画只用 transform/opacity（合成器友好）；`prefers-reduced-motion: reduce` 下全部动画、过渡、平滑滚动停用且内容直接可见；装饰性波形**不播放声音也不假装在播**——卡片标注「界面示意 · 波形是装饰动画，不是真实音频」，遵守产品原型边界「不能用蜂鸣声冒充小说配音」。

## 6. 响应式布局建议

移动优先收敛为三档，官网已实现并实机验证（390px 零横向溢出）：

| 断点 | 布局 |
| --- | --- |
| ≥ 1024px（桌面基准 1440） | Hero 双栏（文案 1.04fr / 播放器 0.96fr）；卖点 4 列；流程 4 列连线；声音区双栏；部署 3 列（命令卡跨全宽） |
| 768–1023px（平板） | Hero 与声音区改单栏；卖点 2 列；流程 2 列；部署 2 列；命令卡占满整行 |
| < 768px（手机，对齐产品「手机优先听书」） | 全部单栏；导航折叠为汉堡菜单（aria-expanded）；CTA 拉通等宽；流程连线隐藏；代码块容器内横向滚动（复制按钮不受影响）；触控目标 ≥ 42px |
| ≤ 420px | 收紧页边距与播放器内边距，音色胶囊缩号防折行 |

对应产品属性的说明：产品桌面负责制作、手机负责听书（PRODUCT.md），所以官网在手机端**优先保证播放器演示与部署命令可用**，编辑类功能区降级为纯内容阅读。

## 7. 可访问性要求

以产品 WCAG AA 目标为底线，官网逐条落实并实测：

- **对比度**：全部文字/背景组合以脚本按 WCAG 相对亮度公式实算（见 §4 表格），正文全部 ≥ 7:1（AAA），最弱的按钮对也有 6.6:1；焦点描边对背景 ≥ 3:1。
- **语义与键盘**：`header/nav/main/section/footer` 地标 + 「跳到主要内容」跳链；全部交互是原生 `button/a/details`，无 `tabindex`hack；焦点环 2px 描边可见；空格/回车原生触发。
- **读屏**：装饰波形、光晕、播放头 `aria-hidden`；音色胶囊用 `aria-pressed` 表达单选态；播放状态与情绪读数用 `aria-live="polite"`；主题按钮的 `aria-label` 随状态改写；图标按钮全部有可访问名称。
- **动效与偏好**：`prefers-reduced-motion` 全停（含 JS 侧平滑滚动）；音频不自动播放——演示播放器初始为暂停态。
- **诚实话术**：演示数据明确标注虚构；不伪造进度、不伪造音频，继承产品「禁止伪造精确金额/进度」的文案纪律。
- **性能与隐私**：零外部请求、零字体下载、零第三方脚本（页脚明示），Lighthouse 友好。
